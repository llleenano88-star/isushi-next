# iSushiClub: как запустить сайт

Сайт на Next.js + Supabase. Код написан, но ни разу не собирался на реальном окружении, поэтому первый запуск проверьте на тестовых данных.

## Что нужно

- Компьютер с Windows, Mac или Linux
- Node.js 20+ (nodejs.org, версия LTS) и Git (git-scm.com)
- Бесплатные аккаунты: GitHub, Supabase, Vercel
- Для подключения кухни: доступ к iiko Cloud (api login, ID организации, ID терминальной группы)

## Часть 1. Запуск на своём компьютере (без iiko)

**1. Распакуйте архив** isushi-next.zip. Откройте терминал (Windows: PowerShell) в папке isushi-next и выполните:

    npm install

**2. Создайте проект Supabase.** supabase.com → New project. Придумайте пароль базы, дождитесь создания (1–2 минуты). Затем Project Settings → API и скопируйте три значения: Project URL, anon public key, service_role key. Ключ service_role секретный, никому его не показывайте.

**3. Создайте таблицы.** Supabase → SQL Editor → New query. По очереди вставьте и запустите (Run) содержимое файлов из папки supabase/migrations, строго в таком порядке:

1. 001_init.sql
2. 002_rate_limit.sql
3. 003_push.sql
4. 004_product_images.sql

После первого файла в базе появится тестовое меню.

**4. Настройки.** Скопируйте файл .env.example в новый файл .env.local и заполните:

| Переменная | Что вписать |
|---|---|
| NEXT_PUBLIC_SUPABASE_URL | Project URL из шага 2 |
| NEXT_PUBLIC_SUPABASE_ANON_KEY | anon public key |
| SUPABASE_SERVICE_ROLE_KEY | service_role key |
| CRON_SECRET | любая длинная случайная строка |
| NEXT_PUBLIC_VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY | команда `npx web-push generate-vapid-keys` |
| VAPID_SUBJECT | mailto:ваш@email |

Остальное пока оставьте пустым.

**5. Запуск.**

    npm run dev

Откройте http://localhost:3000. Должно показаться меню. Добавьте блюдо в корзину и оформите заказ. Заказ сохранится в базе.

**6. Вход по email (для личного кабинета и админки).** В Supabase: Authentication → URL Configuration → Redirect URLs, добавьте http://localhost:3000/auth/callback.

## Часть 2. Выкладка в интернет

**1. GitHub.** Создайте пустой репозиторий isushi-next. В папке проекта:

    git init
    git add .
    git commit -m "first"
    git branch -M main
    git remote add origin https://github.com/ВАШ_ЛОГИН/isushi-next.git
    git push -u origin main

Файл .env.local в репозиторий не попадёт (он в .gitignore), так и должно быть.

**2. Vercel.** vercel.com → Add New → Project → выберите репозиторий. В разделе Environment Variables добавьте все переменные из .env.local. В SITE_URL впишите адрес будущего сайта (сначала адрес вида ваш-проект.vercel.app). Нажмите Deploy.

**3. Supabase.** Authentication → URL Configuration: добавьте https://ВАШ-САЙТ/auth/callback в Redirect URLs, а в Site URL впишите адрес сайта.

**4. Письма для входа.** Встроенная почта Supabase шлёт только несколько писем в час. Для работы с клиентами подключите свой SMTP: Authentication → SMTP Settings.

## Часть 3. Администратор

1. Откройте /login на сайте и войдите по email (придёт ссылка).
2. В Supabase → SQL Editor выполните (подставьте свой email):

       update profiles set role='admin' where id=(select id from auth.users where email='ваш@email');

3. Откройте /admin. Там заказы (смена статуса), товары (добавить, изменить, скрыть, загрузить фото).

## Часть 4. Подключение iiko

1. Добавьте в Vercel переменные и нажмите Redeploy:

| Переменная | Что вписать |
|---|---|
| IIKO_API_LOGIN | api login из iiko Cloud |
| IIKO_ORGANIZATION_ID | ID организации |
| IIKO_TERMINAL_GROUP_ID | ID терминальной группы (запрос iiko /api/1/terminal_groups или поддержка iiko) |
| IIKO_WEBHOOK_SECRET | придумайте длинную строку |
| IIKO_CITY | город доставки |

2. Загрузите меню из iiko. Windows PowerShell (в других системах пишите `curl`):

       curl.exe -H "Authorization: Bearer ВАШ_CRON_SECRET" https://ВАШ-САЙТ/api/cron/sync-menu

   В ответе придёт число категорий и товаров. Дальше меню обновляется само каждые 3 часа.

3. Зарегистрируйте вебхук (один раз), чтобы статусы заказов приходили из iiko:

       curl.exe -H "Authorization: Bearer ВАШ_CRON_SECRET" https://ВАШ-САЙТ/api/iiko/register

4. Оформите тестовый заказ и проверьте, что он появился в iiko. В /admin у заказа, не ушедшего в iiko, будет пометка «не в iiko».

Возможные доработки при первом тесте: адрес доставки уходит в iiko строкой (улица и дом одним полем), способ оплаты передаётся комментарием. Если iiko это не принимает, нужны отдельные поля улицы и дома и ID типов оплаты.

## Часть 5. Свой домен

Vercel → проект → Settings → Domains → добавьте isushiclub.ru и пропишите DNS-записи, которые покажет Vercel. Затем обновите SITE_URL и Redirect URLs в Supabase на новый адрес.

## Дополнительно (по желанию)

- **Капча Turnstile.** dash.cloudflare.com → Turnstile → создайте виджет. Ключи впишите в NEXT_PUBLIC_TURNSTILE_SITE_KEY и TURNSTILE_SECRET.
- **Иконки приложения.** Замените public/icons/192.png и 512.png на свой логотип (квадрат, без прозрачных краёв) и выложите заново.
- **Установка на телефон.** Android: плашка «Установить» на сайте. iPhone: в Safari «Поделиться» → «На экран Домой». Push на iPhone работают только после установки.

## Если что-то не работает

| Проблема | Что проверить |
|---|---|
| Меню пустое | Выполнены ли миграции, верны ли URL и anon key в .env.local или Vercel |
| Ссылка из письма не открывает кабинет | Redirect URLs в Supabase |
| /admin перекидывает на главную | Выполнен ли SQL с ролью admin для вашего email |
| Заказ «не в iiko» | Логи Vercel (Logs), запись `iiko createDelivery failed`, переменные IIKO_* |
| Ошибка на `npm run build` | Скопируйте текст ошибки и отправьте на разбор |
| Фото не загружается | Выполнена ли миграция 004, вы вошли как админ |
